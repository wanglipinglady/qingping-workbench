## 01 定位修正

### 1.1 战略前提

**平台化在未来不予考虑。** 产品定位收敛为「**个人超级个体工作台**」——服务于一个人的知识、内容与专业变现，而不是面向外部用户的功能矩阵。

由此推导出三条硬性约束：

1. **不为假想用户设计功能**。所有模块必须有本人当下的真实使用场景，否则不做。
2. **不重复造已有轮子**。已经跑通的自研项目（mom_qa_mvp / ielts_apply_seek）优先复用，不在工作台内重写。
3. **维护成本优先于功能数量**。超级个体的核心资源是注意力，任何增加双份维护的扩展都要否决。

### 1.2 超级个体的三条主线

| 主线 | 目标 | 现有承载 | 缺口 |
|---|---|---|---|
| 专业变现 | 工业 AI 咨询 + MOM/MES/WMS 交付 | mom_qa_mvp（领域 RAG 问答） | 能力已够用，缺「并入工作台」的统一入口 |
| 内容生产 | 公众号「苹之苹之」持续输出 | WeChatWriter 写作专家 + 知识库 | 缺「原料入口」（剪藏）与「复盘机制」（日报） |
| 个人成长 | 英语能力、知识积累 | ielts_apply_seek + 知识库 | 缺数据打通，而非缺功能 |

> **核心判断**：工作台的价值不在于「又一个对话框」，而在于成为**自动化中枢 + 知识资产库 + 输出流水线**。

### 1.3 与愿景画布原路线图的冲突点

| 原路线图条目 | 冲突 | 处置 |
|---|---|---|
| Phase 4 生态建设（插件市场、开发者社区、多语言、开放 API） | 面向外部开发者，属平台化 | **删除** |
| Phase 5「每个人都拥有 AI 伙伴」 | 平台叙事 | 收敛为「我一个人的 AI 伙伴」 |
| Phase 3 领域专家包（创作 / 研究 / 营销） | 泛人群功能 | 按主线裁剪，只保留内容生产相关 |
| Phase 3 工作流模板中心 | 分享属性，属平台化 | **删除**（可保留个人私有模板） |
| Phase 2 浏览器剪藏插件 | 与个人主线高度契合 | **保留并提前优先** |

## 02 市场案例调研

### 2.1 姜 dora「AI 外脑」

调研结论（来源：脉脉《百万头部博主 Dora 的个人 AI 工作流拆解》）：

- 关键不是工具数量，而是**工作流重构**：把高频重复劳动（抓数据、排日程、回邮件、渲染视频）整体交给 AI 自动执行。
- 技术路径：Trae Work / Dify 编排 API + 飞书表格 + 私有知识库，**定时任务夜间运行**，次日直接看结果。

**可借鉴点**：工作台必须具备「**定时任务 + 次日看结果**」的能力。纯对话式交互无法承载超级个体的自动化需求，这是当前技术专家组（状态机驱动）之外的结构性缺口。

### 2.2 一人公司「数字员工」

调研结论（来源：新浪财经《花钱雇AI当同事，我的生意怎么样了？》）：

- 团队 = 1 人 + 4 个数字员工（Claude 文案 / Fin 客服 / Cursor 代码 / 自动化盯投放）。
- 每天早 9 点打开自己搭的**数据看板**，上面跑着 5 个自动化任务（竞品价格监控、Listing 草稿、12 小时数据汇总等）。

**可借鉴点**：**多智能体分工 + 日报看板**是超级个体的标准形态。技术专家组已有「架构师/程序员/审查员/测试员」分工雏形，但缺少「按日汇总」的看板层。

### 2.3 《打造第二大脑》（PARA 方法）

调研结论（来源：小宇宙《绿海龟书社》Vol.53）：

- 信息处理三阶段：**识记 → 联结 → 创新**，多数人只停在「识记」。
- 抓取阶段的核心误区是**抓太多**——四类值得留存的标准之外一律不留。

**可借鉴点**：剪藏只是「识记」，价值低。真正的价值在「联结与复盘」，这直接决定了**学习日报不是可选项，而是剪藏的价值兑现环节**。

### 2.4 Obsidian Second Brain 插件

调研结论（来源：Obsidian 社区插件页）：

- 把散乱笔记自动编译为结构化 wiki，生成双向链接、语义搜索，并提供**引用自己知识**的 AI 对话。

**可借鉴点**：知识库应从「检索」升级为「**自动编译 + 概念/实体抽取 + 引用溯源**」。mom_qa_mvp 已实现引用溯源（[来源X] 标注），可直接复用。

### 2.5 调研小结

| 案例 | 核心机制 | 对本工作台的启示 |
|---|---|---|
| 姜 dora AI 外脑 | 定时自动化 + 私有知识库 | 需要「定时任务」与「每日结果视图」 |
| 一人公司数字员工 | 多智能体分工 + 数据看板 | 需要「日报看板」，复用专家组分工 |
| 第二大脑 PARA | 识记→联结→创新 | 剪藏之后必须有复盘环节 |
| Obsidian Second Brain | 自动编译 + 双向链接 + 引用 | 知识库升级方向：编译与联结 |

## 03 现状盘点

### 3.1 工作台已有能力

| 层 | 内容 |
|---|---|

### 3.2 可复用的自研资产

**mom_qa_mvp（电子 MOM 智能问答）**

- 文档解析覆盖 14 类格式：PDF / DOCX / DOC / TXT / MD / XLSX / XLS / CSV / PPTX / VSDX / XMIND / HTML / JSON / XML。
- RAG 链路完整：bge-small-zh-v1.5 嵌入 + Chroma 持久化 + 置信度阈值兜底 + 引用溯源 + 反馈闭环（SQLite）。
- 分类标签体系：8 类业务分类 + 子类型 + sidecar `.docmeta.json` 元数据透传。
- 参数基线：CHUNK_SIZE=512、OVERLAP=128、TOP_K=4、阈值 0.30。
- 检索自测：Recall@K = 100%（5/5）。

> **结论**：这套 **ingestion 管线是剪藏模块的直接底座**，剪藏只需替换「输入源」（URL → 文档）与前端入口，无需重写解析与向量化。

**ielts_apply_seek（雅思备考助手）**

- 语音训练五步闭环：中文感想改写 → 音标拼读展示 → 标准音合成 → 跟读录音对比 → 纠音记录与 journal 模板导出。
- TTS：edge-tts 默认（免费），MiniMax T2A 回退；音标解析 CMUdict + espeak-ng 本地化。
- 部署：118.190.148.121 `/opt/ielts_apply_seek`，systemd `ielts-web`，uvicorn 8001，Nginx 反代。
- 形态：Web + 微信小程序（AppID `wx286309bc641b1d79`）多端同步。

> **结论**：口语训练已是完整独立产品。工作台**不应重写**，只做入口聚合与学习数据打通。

**knowledge_base（个人知识库在线管理）**

- 仓库当前不可用：clone 后为空目录，`git log` 报 `current branch appears to be broken`。
- **待确认**：该仓库是否已废弃 / 迁移 / 私有化。确认前不作为复用依据。

### 3.3 痛点提炼（源自个人网站服务清单）

个人网站 `wanglipingresume.com` 的「服务」板块明确列出四项：工业 AI 落地咨询、MOM/MES/WMS 交付、**技术内容创作与公众号代运营**、快速原型与 AI 工具开发。

其中「技术内容创作与公众号代运营」要求**稳定的选题与素材供给**，而当前工作台只有「写作」环节（WeChatWriter），上游素材采集与下游复盘均缺失。这就是剪藏与日报的**需求来源**——不是凭空加功能，而是补齐已经对外承诺的能力。

## 05 Phase 3 优先级建议

### 5.1 排序结论

**选材剪藏（P0）→ 学习日报（P1）→ 雅思口语轻集成（P2）**

### 5.2 逐项论证

#### P0 选材剪藏

| 维度 | 评估 |
|---|---|
| 价值 | 最高。同时服务三条主线：为内容生产供料、为专业变现积累领域素材、为个人成长沉淀输入 |
| 成本 | 最低。复用 mom_qa_mvp 的解析/切分/向量化/分类管线，工作量集中在前端入口与 URL 抓取 |
| 依赖 | 无前置依赖，可立即启动 |
| 风险 | 网页正文抽取质量不稳定（广告、反爬、动态渲染） |

**实现要点**

1. 入口：浏览器书签脚本（bookmarklet）→ 调用后端 `/api/clip`，避免开发完整浏览器扩展。
2. 抓取：URL → readability 正文抽取 → 转 Markdown → 复用现有 ingestion 管线。
3. 元数据：复用 `docmeta.json` sidecar 机制，写入来源 URL、作者、抓取时间、分类、标签。
4. 去重：按 URL 规范化 + 内容指纹（SimHash）双校验。
5. 最低可用标准：能剪、能分类、能在知识库检索到。

#### P1 学习日报

| 维度 | 评估 |
|---|---|
| 价值 | 高。是「联结与复盘」环节，把输入转成输出，符合第二大脑方法论；直接产出公众号选题 |
| 成本 | 中。需要定时任务框架 + 汇总 Prompt + 历史数据读取 |
| 依赖 | **依赖 P0**。没有剪藏原料，日报无内容可写，会沦为形式 |
| 风险 | 流于形式（为写而写）、Token 成本累积 |

**实现要点**

1. 定时：每日 22:00 触发，复用现有 systemd timer 或应用内调度。
2. 输入：当日剪藏条目 + 当日知识库检索记录 + 当日对话记录。
3. 输出结构：今日新增素材摘要 / 三个可深挖的点 / 一条可写选题 / 明日待办。
4. 存储：Markdown 落库，同步到 Obsidian（已有同步调用文档可复用）。
5. **硬约束**：日报必须能产出「可执行选题」，否则视为失败设计。

#### P2 雅思口语（轻集成）

| 维度 | 评估 |
|---|---|
| 价值 | 中。服务个人成长单一主线 |
| 成本 | 重写成本极高，轻集成成本极低 |
| 依赖 | 无 |
| 风险 | 若在工作台内重写训练逻辑，将产生**双份维护**，违背 1.1 节约束 3 |

**处置建议：不做功能重写，只做三件事**

1. **入口聚合**：工作台首页增加「雅思口语」卡片，跳转 ielts_apply_seek（Web 或小程序）。
2. **数据回流**：口语训练记录（日期、练习时长、纠音次数、错词）以只读方式汇总到工作台，供日报引用。
3. **词汇联动**：错词本写入工作台知识库，形成「个人薄弱点知识库」，可被 RAG 检索。

> 若上述三项之外还想加功能，属于「新项目」范畴，应回到 ielts_apply_seek 仓库做，不在本工作台。

### 5.3 优先级对比表

| 模块 | 价值 | 成本 | 依赖 | 复用度 | 结论 |
|---|---|---|---|---|---|
| 选材剪藏 | 高 | 低 | 无 | 高（mom_qa_mvp 管线） | **P0 立即做** |
| 学习日报 | 高 | 中 | 依赖剪藏 | 中（复用 Obsidian 同步） | **P1 紧随其后** |
| 雅思口语 | 中 | 高（重写）/ 极低（集成） | 无 | 低 | **P2 只做轻集成** |

```
选材剪藏 ──► 学习日报 ──► 雅思口语轻集成
   │            │              │
   │            └─ 产出选题 ──► WeChatWriter 写作
   │                           │
   └─ 供料 ────────────────────┘
                                │
                     口语错词 ──► 知识库（薄弱点库）
```

**关键路径**：剪藏 → 日报 → 写作，形成「输入—复盘—输出」闭环。雅思口语作为旁挂支线，不阻塞主路径。

## 07 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 剪藏正文抽取质量差，噪声入库污染检索 | 高 | 入库前做 readability 清洗 + 人工一键丢弃；分类置信度低时标记待复核 |
| 日报流于形式，为写而写 | 高 | 以「是否产出可执行选题」作为唯一验收标准；连续 3 日无选题则触发策略调整 |
| 定时任务失败无感知 | 中 | 任务失败写入通知；日报缺失时首页显式提示 |
| Token 成本随日报/剪藏累积 | 中 | 日报用低成本模型；剪藏只做解析与向量化，不调 LLM 生成摘要（可选开关） |
| 雅思口语双份维护 | 中 | 严格限定为「入口 + 数据回流」，功能开发留在 ielts_apply_seek 仓库 |
| knowledge_base 仓库状态不明 | 低 | 先确认仓库状态，再决定是否复用其在线管理能力 |

## 09 待确认事项

1. **knowledge_base 仓库状态**：clone 后为空且分支损坏，需确认是否废弃、迁移或私有化。
2. **mom_qa_mvp 并入方式**：是抽取 ingestion 管线为工作台插件，还是保留独立服务、通过 API 调用？建议前者（减少一份部署），但需评估解析依赖（pdfplumber / antiword / libreoffice）的部署成本。
3. **剪藏入口形态**：bookmarklet 优先，是否后续升级为完整浏览器扩展？建议先用 bookmarklet 验证使用频率。
4. **日报模型选型**：使用低成本模型（如 MiniMax 轻量档）还是本地小模型？取决于日报 Token 量级实测。
5. **是否修订 02-产品愿景画布.md**：本文档与愿景画布第 5.2 / 09 节存在冲突，需决定是「以本文档为准，愿景画布保留历史」还是「同步修订愿景画布」。
