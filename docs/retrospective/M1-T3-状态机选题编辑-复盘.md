# M1·T3 复盘：状态机引擎 + 选题编辑角色

## 1. 任务概述
完成写作助手状态机引擎、4 个专家角色配置、选题编辑角色（含 System Prompt），以及状态机操作的完整 API。

核心交付：

- 4 个专家角色：选题编辑、研究员、结构师、撰稿人
- 选题编辑 System Prompt：完整的选题确认单输出格式
- 4 个状态操作 API：/start /confirm /regenerate /rollback

## 3. 遇到的问题与根因

| 问题 | 根因 | 解决方案 |
|---|---|---|
| MiniMax API 401 | 默认配置的 API 地址是 `api.minimax.chat`，不是 `api.minimaxi.com` | 创建 `.env` 覆盖默认配置 |

## 6. 经验沉淀

1. **配置管理**：默认配置可能与实际环境不符，`.env` 文件是覆盖默认值的最佳方式。永远不要依赖默认配置跑生产环境。
2. **API 设计**：语义清晰的多个 API（/start /confirm /regenerate /rollback）比一个万能 API（/state?action=xxx）更好，前端对接更直观，文档更清晰。
3. **版本管理**：每次 AI 生成都保存版本，这是非常重要的设计。用户可以对比历史版本，选择最好的，也可以回退到之前的版本。
4. **消息历史**：记录完整的对话历史不仅是为了调试，更是为了后续的重新生成操作——AI 需要看到之前的对话上下文才能理解用户的修改建议。
5. **状态机设计**：写作状态机的核心是「每个工作状态完成后默认暂停」，用户可以选择确认、重生成、回退或切换专家。这种设计比自动流水线更灵活，也更符合写作的创造性本质。
6. **Prompt 工程**：选题编辑的 System Prompt 超过 4000 字，详细定义了输出格式（选题确认单）、职责、工作原则。结构化的 Prompt 是 AI 输出质量的保证——格式越明确，输出越可控。
