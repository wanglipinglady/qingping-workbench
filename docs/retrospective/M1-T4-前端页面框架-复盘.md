# M1·T4 复盘：前端页面框架

## 1. 任务概述
完成微信公众号写作助手的前端页面框架，包括 API 层封装、Zustand 状态管理、主页面组件，以及路由和侧边栏菜单注册。

核心交付：
- API 层：12 个接口封装（会话 CRUD + 状态操作 + 资料/输出）
- Store 层：Zustand 状态管理（会话、输出、加载状态、12 个 action）
- 页面层：主页面组件（左中右三栏布局 + 3 个交互弹窗）
- 路由菜单：App.tsx + Sidebar.tsx 注册

## 6. 经验沉淀

1. **前端分层清晰**：API 层（接口封装）→ Store 层（状态管理）→ 页面层（UI 渲染），三层分离，每层职责明确，后续扩展很顺畅
2. **加载状态细分**：不要只用一个 `loading: boolean`，要细分到每个操作（loading.start/loading.confirm/...），这样 UI 可以精准显示哪个按钮在加载
3. **参考现有实现**：项目已有 TechExperts 页面作为参考，沿用相同的布局模式和组件风格，保证一致性，也减少决策成本
4. **构建验证**：前端代码写完一定要跑 `vite build` 验证，tsc 的警告可能是历史遗留，但 vite build 必须通过才能交付
5. **状态机的前端表达**：7 个阶段用进度条可视化，当前专家用彩色标签展示，输出内容用 Markdown 渲染+版本标签，这些细节让抽象的状态机变得直观易懂
